# Deploying JamiiChat

Nothing is deployed yet. `netlify.toml` and `render.yaml` are written and
correct; what is missing is the accounts and services, which have to be created
under your own logins.

Frontend → Netlify. API + WebSocket server → Render. Data → MongoDB Atlas.

The API and the WebSocket server share one HTTP server (`backend/server.js`), so
there is only one backend service to provision. Render supports WebSockets on
the free plan.

## Order matters

Each step below produces a value the next one needs, so do them in order.

### 1. GitHub

No remote exists yet, and `gh` is not authenticated on this machine.

```bash
# create David-mwendwa/JamiiChat on github.com first, then:
git remote add origin git@github.com:David-mwendwa/JamiiChat.git
git push -u origin main
```

### 2. MongoDB Atlas

Create a free M0 cluster and a database user. Under Network Access, allow
`0.0.0.0/0` — Render's outbound IPs are not fixed on the free plan.

Take the connection string and append the database name:

```
mongodb+srv://<user>:<password>@<cluster>.mongodb.net/jamii?retryWrites=true&w=majority
```

Seed it once from your machine:

```bash
DATABASE_URL="<the string above>" npm run seed --prefix backend
```

That writes ~22 accounts, 43 posts, follows, likes, notifications and two
conversations. Without it the deployed app is an empty social network, which
demos as broken.

### 3. Render

New → Blueprint, point it at the repo. `render.yaml` defines the service.

Fill in the two `sync: false` variables in the dashboard:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the Atlas string from step 2 |
| `PROD_FRONTEND_URL` | the Netlify URL from step 4, **no trailing slash** |

`JWT_SECRET` is generated by Render; do not set it yourself.

`PROD_FRONTEND_URL` is a chicken-and-egg with step 4 — deploy Render first with
it blank, get the Netlify URL, then come back and set it. The service restarts
on save.

### 4. Netlify

Add new site → import the repo. `netlify.toml` sets the base directory, build
command and publish directory, so accept what it detects.

Set one environment variable under Site configuration → Environment variables:

| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://jamii-api.onrender.com/api/v1` |

The socket URL is derived from this by stripping `/api/v1`, so there is only one
value to keep in sync. It is read at build time — changing it needs a redeploy,
not just a restart.

Then go back to Render and set `PROD_FRONTEND_URL` to the Netlify URL.

### 5. Check it end to end

- `https://jamii-api.onrender.com/health` returns `{"status":"ok"}`
- Sign in with `demo@jamii.app` / `demo12345`
- The home feed has posts in it
- **Open Messages in two browsers, signed in as different accounts, and send a
  message.** This is the one thing a smoke test of the REST API will not catch:
  if `PROD_FRONTEND_URL` is wrong, the feed loads normally and only real-time
  silently fails.

## Known limitations in production

**Uploads do not survive a deploy.** Avatars and post images are written to
`backend/public/media` on disk, and Render's filesystem is ephemeral. The seed
artwork survives because it is committed to the repo; anything a user uploads
is lost on the next deploy. Moving uploads to Cloudinary is the fix and is not
done.

**The free tier sleeps.** After ~15 minutes idle the service stops, and the
first request wakes it with a delay of 30 seconds or so. The socket drops while
it sleeps; the UI shows "Reconnecting — live updates are paused" and recovers on
its own, but the first visit after a quiet period is slow.

**No custom domain, no email.** Password reset is not built, so no mail provider
is needed.

## After it is live

Add the portfolio entry — this is a workspace convention, not an optional step:

1. Create `portfolio/src/assets/projects/jamii.png` using JamiiChat's real palette
   (violet `#7C3AED` / amber `#F59E0B`), Plus Jakarta Sans, and the shield-free
   three-node mark from `frontend/public/logo.svg`.
2. Add the entry to `portfolio/src/data/projects.js` with the live URLs.
3. Push `portfolio` — that push is what ships it to production.
